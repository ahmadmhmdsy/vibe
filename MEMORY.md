## Lessons

| Date | Lesson | Reference |
|---|---|---|
| 2026-09-28 | Batch `set VAR=value && next` captures the space before `&&` into the value. In start.bat this made `VITE_API_URL=http://localhost:8123 ` (trailing space), so every frontend fetch threw "Failed to parse URL" and clicks silently did nothing. Fix: `set VAR=value&& next` (no space) or `set "VAR=value"`. When debugging env-var issues on Windows, dump the actual value with `set VAR` — never trust the visible line. | start.bat; apps/vibe/src/lib/api.ts |
| 2026-09-29 | `Tool.from_function` with a single-parameter function is a **single-input tool**: langchain rejects any call whose argument count ≠ 1 (`Too many arguments to single-input tool`). No-arg tools (LLM passes `{}`) and multi-arg calls both fail. Fix: use `StructuredTool.from_function` + a `**kwargs` adapter that collects the LLM's arguments into one dict — every input shape (`{}`, optional, multi-arg) then reaches the handler intact. The error message itself says "Consider using StructuredTool instead". | services/vibe/src/vibe/tools/registry.py (`_adapt_handler`) |
| 2026-09-29 | LangChain's `AIMessage.usage_metadata` is a pydantic model that **requires `total_tokens`** — omitting it raises `ValidationError` even when `input_tokens`/`output_tokens` are present. When building a stub LLM for tests, always include `total_tokens`. Also: `UsageTracker.session_total` is a coroutine — FastAPI routes must `await` it (a non-awaited call returns a coroutine and fails with `'coroutine' object has no attribute '__dict__'`). | services/vibe/src/vibe/usage/tracker.py; services/vibe/tests/test_usage.py |
| 2026-09-29 | On Windows, `Path.relative_to` yields backslashes (`srcApp.tsx`). Any file-list API consumed by a web frontend must normalize to forward slashes (`str(p).replace("\\", "/")`) or the frontend's `path === "src/App.tsx"` checks fail. | services/vibe/src/vibe/api/routes/sessions.py (`list_files`) |
| 2026-09-29 | zustand v5 selectors that return fresh references (`?? []`) cause infinite re-render loops. Use `useShallow` from `zustand/react/shallow` for array/object selectors, or select primitives individually. | apps/vibe/src/features/chat/MessageList.tsx |
| 2026-09-29 | The edit tool rejects import-line changes (it matches literal text; import lines often have trailing whitespace or different formatting). When updating imports, rewrite the whole file with the write tool instead. | apps/vibe/src/features/chat/store.ts |
| 2026-09-29 | Vite's file watcher crashes (EBUSY) when the write tool's temp files land inside the watched directory. Keep build scripts outside `apps/vibe` and restart vite after writes that touch source files. | apps/vibe/ (vite watcher) |
| 2026-09-29 | PowerShell eats `@e3` refs (splatting). In pwsh commands, quote them (`'@e3'`) or use CSS selectors instead. agent-browser relaunches its browser per pwsh call, so chain open+act+snapshot in one script. | pwsh tool usage |
| 2026-09-29 | Monaco editor loads from CDN by default. In offline/air-gapped environments, configure `loader.config({ monaco })` with a local monaco instance or use the `@monaco-editor/react` `loader` prop with a local path. | apps/vibe/src/features/code/CodePanel.tsx |
| 2026-09-29 | SSE `EventSource` has no native reconnect with last-event-id. The client must track `lastSeq` and pass it as `after_seq` on reconnect; the server replays from that seq. Without this, reconnects lose events. | apps/vibe/src/lib/sse.ts; services/vibe/src/vibe/api/routes/sessions.py |
| 2026-09-30 | `EventSource.onmessage` delivers the event's data field with the `data: ` prefix and trailing blank line **already stripped** — `msg.data` is the bare JSON. An SSE client whose `parse()` regex requires `data: (.+)\n\n` therefore matches nothing, returns null, and silently drops every event (the UI never updates, with no console error). Symptom: chat sends succeed and the backend persists the reply, but nothing renders. Fix: fall back to the raw string when the frame regex misses (`const json = match ? match[1] : raw`), and wrap `JSON.parse` in try/catch. Unit-test `parse` with the onmessage shape, not only raw frames. | apps/vibe/src/lib/sse.ts; apps/vibe/src/lib/__tests__/sse.test.ts |
| 2026-09-30 | **A `@layer` statement only wins if it appears before the first `@import`.** Layer order is fixed by a layer's *first* appearance, so `global.css` importing `components.css` above `@layer reset, base, components, utilities;` silently reordered the cascade to components→reset→base: every base element rule then beat every component rule. Symptoms were subtle and CSS-only — `.btn-primary` computed to `--bg-raised` (the app had **no visible primary action**), `.btn-sm`/`.icon-btn` fell back to the 32px base button height. Verify a cascade fix by reading *computed* styles in a browser, never by reading the sheet. | apps/vibe/src/styles/global.css |
| 2026-09-30 | **In this repo the feature sheets (`chat.css`, `code.css`, `preview.css`, `sessions.css`, `settings.css`) are unlayered, so they beat everything in `@layer components` regardless of specificity.** A responsive rule in `app.css` that hides a panel must therefore raise specificity, not just add a class: `.app-side > * { display: none }` lost to `.preview-panel { display: flex }` (equal specificity, later source order), which made the mobile Code/Preview tabs show both panels stacked. Fix: qualify with the state attribute — `.app-body[data-mobile-tab] .app-side > *`. | apps/vibe/src/styles/app.css |
| 2026-09-30 | **Quick recipe — "chat sends but no agent reply renders" (least steps):** (1) `GET /sessions/{sid}/messages` on the backend — reply present ⇒ backend healthy, break is the frontend SSE path. (2) Browser console shows **no error** — this failure is silent by design. (3) Fix `SSEClient.parse` in `apps/vibe/src/lib/sse.ts`: accept the onmessage shape — `const json = match ? match[1] : raw;` + try/catch around `JSON.parse`. (4) Run the regression tests: `cd apps/vibe && pnpm vitest run src/lib/__tests__/sse.test.ts`. (5) Verify in the browser: send a message, assert a `.message-assistant` node with the reply appears. | apps/vibe/src/lib/sse.ts; apps/vibe/src/lib/__tests__/sse.test.ts |
| 2026-10-04 | **A single shared `asyncio.Queue` per session makes SSE subscribers compete, not fan out.** `EventBus` kept one queue per session id, so two tabs (or a reconnect overlapping its predecessor) each received a *random subset* of events — and events published while nobody was connected stayed queued and were replayed to the next client on top of the log replay. Fix: one queue per subscriber in a `set`, registered eagerly inside `subscribe()` (before any await, so nothing published between subscribe and first read is lost), a `put_nowait` + drop-oldest guard so one dead client cannot grow unbounded, and `aclose()` to unregister. Single-subscriber tests hid this completely — always test fan-out with two subscribers. | services/vibe/src/vibe/events.py; services/vibe/tests/test_events.py |
| 2026-10-04 | **Ephemeral stream frames must draw from the same sequence counter as durable events.** `text_chunk`/`turn_complete` were published with `seq=0` because they were never stored, so the client's `lastSeq` stayed 0 and every reconnect asked for `after_seq=0` — re-replaying the whole log. Fix: `EventLog.next_seq(sid)` reserves a monotonic seq without storing, and the client only advances `lastSeq` on a *strictly greater* seq. Corollary: the SSE route must subscribe **before** replaying the log and skip any live event whose seq the replay already delivered, otherwise the fix trades lost events for duplicated ones. | services/vibe/src/vibe/events.py; services/vibe/src/vibe/api/routes/sessions.py; apps/vibe/src/lib/sse.ts |
| 2026-10-04 | **A camelCase↔snake_case seam fails silently and returns 200.** `PATCH /providers/{id}` filtered the body against `{"name","base_url","api_key","models"}` while the frontend sent `baseUrl`/`apiKey`, so every field was dropped, the response echoed the *old* values, and the UI toasted "Provider updated". The fix is an explicit bidirectional field map that 400s when nothing is updatable — never a silent filter. Whenever two languages meet at a wire format, assert a full round-trip (write → re-read), not just the response body. | services/vibe/src/vibe/api/routes/providers.py; services/vibe/tests/test_bridge_fixes.py |
| 2026-10-04 | **A "stop" that only sets a store flag is not a stop.** The chat store's `stopRequested` was written by the Composer and read by *nothing*, and the backend had no way to cancel a run — the Stop button changed the button's label and let the model call keep running. A real stop needs a cancellable handle: run the agent loop in an `asyncio.Task`, cancel it from the abort route, and distinguish an abort (`task.cancelled() and handle.abort_requested` ⇒ report it) from a client disconnect (`⇒ request_abort() and re-raise`). Check for a dead flag with a grep for its readers before trusting any UI control. | services/vibe/src/vibe/runs.py; services/vibe/src/vibe/api/routes/chat.py; apps/vibe/src/features/chat/Composer.tsx |
| 2026-10-04 | **React keys from an array index corrupt a streaming list.** Chunks append to the last message, so with `key={i}` React reuses the wrong node when history loads or a turn is inserted. Give every message a stable id at creation and track *which* message the current turn streams into, so a late or replayed chunk can never mutate a finished message. Generated ids must be namespaced (`msg-1`, not `m1`) — a plain counter collided with hand-written fixture ids and made two messages share a key. | apps/vibe/src/features/chat/store.ts; apps/vibe/src/features/chat/MessageList.tsx |
| 2026-10-04 | **pnpm 12 passes `--` through to the script, so `pnpm run test -- --run` starts vitest in watch mode and never exits** (it looks like a hang; the first `run_code` deadline killed it). Use `pnpm test --run` or `pnpm exec vitest run`. Long frontend commands belong in a background job with output redirected to a file (`pnpm exec vitest run *> out.txt`), because `Select-Object -Last N` buffers everything until the process ends and shows nothing while it runs. | apps/vibe/package.json; HANDOFF.md |
| 2026-10-04 | **`Path(os.environ.get("X", default))` turns an *empty* env var into the current directory.** `Path("")` is `Path(".")`, so `VIBE_WORKSPACE_DIR=` (or an unset-but-present var) silently pointed the whole install at the process CWD. Use `os.environ.get("X") or default`, and normalise once in the settings object: `Path(v).expanduser().resolve()`. Do the same for a "host" field — a `getenv` that returns `""` binds uvicorn to every interface. | services/vibe/src/vibe/config.py; services/vibe/tests/test_persistence.py |
| 2026-10-04 | **`TestClient.stream(...)` + `iter_bytes()` hangs on an infinite SSE endpoint** even with a `break` in the loop: exiting the `with` block waits on a response body that never ends, and the whole pytest run stalls with no output (it looked like a slow suite, not a failure). The pattern that works — already used by `test_sse.py` — is to call the route function directly with a tiny mock `Request`, then consume `resp.body_iterator` inside an `asyncio.wait_for` and cancel. Budget a visible `-v` run when adding a streaming test: a silent hang costs far more than a failure. | services/vibe/tests/test_persistence.py; services/vibe/tests/test_sse.py |
| 2026-10-04 | **You cannot patch a seam that does not exist.** A test that set `executor._spawn = fake` passed a falsy assertion (`[] == ["spawn"]`) because `start_dev_server` inlined `asyncio.create_subprocess_exec` instead of calling `self._spawn()`. When a unit test can only be written by patching a stdlib call, that is the design telling you where the seam belongs. | services/vibe/src/vibe/executor/local.py; services/vibe/tests/test_lifecycle.py |
| 2026-10-04 | **Windows refuses to rename a directory that has open handles, so teardown order is load-bearing.** Deleting a session must stop the dev-server subprocess *before* moving the workspace, and move the workspace *before* deleting the row — otherwise a locked directory either leaks the files or, worse, deletes the row and orphans them. | 2026-10-04 | **Durability needs `PRAGMA user_version`, WAL, a lock *and* `asyncio.to_thread` — each fixes a different failure.** `journal_mode=WAL` + `busy_timeout` stops readers blocking writers; a `threading.Lock` around one shared `sqlite3` connection stops concurrent-request interleaving; `await asyncio.to_thread(...)` keeps a slow disk off the event loop; `user_version` gives the *next* column a supported upgrade path (there was none). | 2026-10-04 | **`$env:TEMP` is the 8.3 short path (`C:\Users\AHMADM~1\...`) while `Path.resolve()` returns the long form**, so a path-equality assertion in a verification script reports a false negative against perfectly correct code. | 2026-10-04 | **`eslint-plugin-react-hooks` v7's flat configs are `configs.flat.recommended`, not `configs.recommended`.** The bare names still exist but are the LEGACY eslintrc shape (a `plugins` array of strings), so spreading one into an eslint 10 flat config fails with `A config object has a "plugins" key defined as an array of strings`.
