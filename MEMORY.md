## Lessons

| Date | Lesson | Reference |
|---|---|---|
| 2026-10-11 | **On a shared workspace, "no agents listed" is not evidence that nothing is writing.** `list_agents` returned an empty list while source files kept changing under `services/vibe/src` (four writes in ninety seconds). Two consecutive full-suite runs gave different failure counts (2 then 6) for that reason, and either number would have been a fabricated gate result. Use file mtimes as the liveness signal; treat a test count as meaningful only after the newest mtime stops moving, and never "fix" a red test whose owning task is still in flight. | artifacts/hardening-progress-log.txt (Round 11) |
| 2026-10-11 | **An assertion written inside a plan is a draft, not a spec — execute it against the real code before believing it.** R3-T1's cap test asserted `len(input.messages) == 2` for `history_messages = 2`; the fix appends the current turn to the replayed window, so the real answer is 3. The same file was wrong about the register total (40 vs 41). Both were caught only because the phase actually ran the steps; a plan's numbers deserve the same suspicion as a remembered one. | docs/superpowers/plans/2026-10-11-local-production-hardening.md §8 R3-T1; artifacts/hardening-r3-report.txt |
| 2026-10-11 | **The system prompt is the one model input deliberately outside the event log.** It is static configuration (code or `VIBE_SYSTEM_PROMPT`), not conversation, so writing it into every session would bloat the transcript and repeat identical text. The cost is real and small: two sessions run under different prompts are indistinguishable from their logs alone. Anything dynamic would need a `session/system_prompt` event instead. | services/vibe/src/vibe/prompts.py; docs/reviews/2026-10-11-full-app-review/02-backend-findings.md §BE-19 |
| 2026-10-11 | **A UI that prints two contradictory sentences passes every test written on good data.** The doctor's first render said "1 blocking problem(s)" and "all checks passed — the app can run on this machine" on adjacent lines, because a regex edit had collapsed an if/elif chain: the success branch was reached whenever there were *no warnings*, regardless of hard failures. It was invisible to 30 green tests and obvious the first time the real binary ran against a held port. Run the artifact in its failing state, not only its happy path. | services/vibe/src/vibe/doctor.py; artifacts/hardening-r5-doctor.txt |
| 2026-10-11 | **A guard that rejects path separators rejects every scoped npm package.** `@types/react` and every `@vitejs/*` plugin contain a `/` that belongs to the *name*, not a path. Any "no slash" safety check must special-case a leading `@` with exactly one separator, or it denies precisely the packages the allowlist was written to permit. | services/vibe/src/vibe/supply_chain.py |
| 2026-10-11 | **`Path.with_suffix(".tmp")` on `providers.json` produces `providers.tmp`** — it replaces the existing suffix instead of appending. Use `with_name(name + ".tmp")` for a sibling temp file, or the atomic swap is swapping the wrong path. | services/vibe/src/vibe/providers/custom.py |
| 2026-10-11 | **Python logging defers %-format validation to emit time, so a bad format string is invisible until the record is rendered.** The VIBE_HOST warning had one `%s` and three arguments; importing and calling the function both looked fine, and only the handler's rendering produced the operator's "--- Logging error ---" traceback instead of the warning. A logging test must exercise the *handler*, not just the call. | services/vibe/src/vibe/api/app.py; artifacts/hardening-r3-report.txt |
| 2026-10-11 | **A replay window and the current message are different things.** `history_messages` caps what is replayed from the log; the turn just sent is appended on top, so `limit=2` produces three messages, not two. The plan's own cap test asserted two and was wrong — the executed test asserts the three contents exactly. Arithmetic in a plan is a claim like any other. | services/vibe/src/vibe/api/routes/chat.py; artifacts/hardening-r3-report.txt |
| 2026-09-28 | Batch `set VAR=value && next` captures the space before `&&` into the value. In start.bat this made `VITE_API_URL=http://localhost:8123 ` (trailing space), so every frontend fetch threw "Failed to parse URL" and clicks silently did nothing. Fix: `set VAR=value&& next` (no space) or `set "VAR=value"`. When debugging env-var issues on Windows, dump the actual value with `set VAR` — never trust the visible line. | start.bat; apps/vibe/src/lib/api.ts |
| 2026-09-29 | `Tool.from_function` with a single-parameter function is a **single-input tool**: langchain rejects any call whose argument count ≠ 1 (`Too many arguments to single-input tool`). No-arg tools (LLM passes `{}`) and multi-arg calls both fail. Fix: use `StructuredTool.from_function` + a `**kwargs` adapter that collects the LLM's arguments into one dict — every input shape (`{}`, optional, multi-arg) then reaches the handler intact. The error message itself says "Consider using StructuredTool instead". | services/vibe/src/vibe/tools/registry.py (`_adapt_handler`) |
| 2026-09-29 | LangChain's `AIMessage.usage_metadata` is a pydantic model that **requires `total_tokens`** — omitting it raises `ValidationError` even when `input_tokens`/`output_tokens` are present. When building a stub LLM for tests, always include `total_tokens`. Also: `UsageTracker.session_total` is a coroutine — FastAPI routes must `await` it (a non-awaited call returns a coroutine and fails with `'coroutine' object has no attribute '__dict__'`). | services/vibe/src/vibe/usage/tracker.py; services/vibe/tests/test_usage.py |
| 2026-09-29 | On Windows, `Path.relative_to` yields backslashes (`srcApp.tsx`). Any file-list API consumed by a web frontend must normalize to forward slashes (`str(p).replace("\\", "/")`) or the frontend's `path === "src/App.tsx"` checks fail. | services/vibe/src/vibe/api/routes/sessions.py (`list_files`) |
| 2026-09-29 | zustand v5 selectors that return fresh references (`?? []`) cause infinite re-render loops. Use `useShallow` from `zustand/react/shallow` for array/object selectors, or select primitives individually. | apps/vibe/src/features/chat/MessageList.tsx |
| 2026-09-29 | The edit tool rejects import-line changes (it matches literal text; import lines often have trailing whitespace or different formatting). When updating imports, rewrite the whole file with the write tool instead. | apps/vibe/src/features/chat/store.ts |
| 2026-09-29 | Vite's file watcher crashes (EBUSY) when the write tool's temp files land inside the watched directory. Keep build scripts outside `apps/vibe` and restart vite after writes that touch source files. | apps/vibe/ (vite watcher) |
| 2026-09-29 | PowerShell eats `@e3` refs (splatting). In pwsh commands, quote them (`'@e3'`) or use CSS selectors instead. agent-browser relaunches its browser per pwsh call, so chain open+act+snapshot in one script. | pwsh tool usage |
| 2026-09-29 | Monaco editor loads from CDN by default. In offline/air-gapped environments, configure `loader.config({ monaco })` with a local monaco instance or use the `@monaco-editor/react` `loader` prop with a local path. | apps/vibe/src/features/code/CodePanel.tsx |
| 2026-09-29 | SSE `EventSource` has no native reconnect with last-event-id. The client must track `lastSeq` and pass it as `after_seq` on reconnect; the server replays from that seq. Without this, reconnects lose events. | apps/vibe/src/lib/sse.ts; services/vibe/src/vibe/api/routes/sessions.py |
| 2026-09-30 | `EventSource.onmessage` delivers the event's data field with the `data: ` prefix and trailing blank line **already stripped** — `msg.data` is the bare JSON.
